# GraalVM Native Image Guide for Stirling-PDF

This guide explains how to build, test, optimize, and benchmark the GraalVM Native Image version of Stirling-PDF.

## Prerequisites
- **OS**: Linux (Ubuntu 22.04+ recommended) or macOS (Apple Silicon supported)
- **JDK**: GraalVM for JDK 25+ (Community or Oracle Enterprise)
- **Memory**: At least 16GB RAM is recommended for compilation
- **Disk**: 10GB+ free space

## Quick Reference

| Task | Command |
|------|---------|
| Quick dev build | `./gradlew :stirling-pdf:nativeCompile -Pnative.profile=quick -PnoSpotless` |
| Standard build | `./gradlew :stirling-pdf:nativeCompile -PnoSpotless` |

## Build Profiles

Three build profiles are available via `-Pnative.profile=PROFILE`:

| Profile | Opt Level | Debug Info | Build Time | Use Case |
|---------|-----------|------------|------------|----------|
| `quick` | `-Ob` | Kept | ~2-3 min | Development iteration |
| `standard` | `-O2` | Stripped | ~5-10 min | Default, CI builds |
| `production` | `-O2` | Stripped | ~8-15 min | Release builds |

```bash
# Fast development builds (minimal optimization, keeps debug info)
./gradlew :stirling-pdf:nativeCompile -Pnative.profile=quick -PnoSpotless

# Standard build (default if omitted)
./gradlew :stirling-pdf:nativeCompile -PnoSpotless

# Full production optimization
./gradlew :stirling-pdf:nativeCompile -Pnative.profile=production -PnoSpotless
```

## CPU Architecture

The default architecture is `compatibility` (runs on any x86_64 CPU). Override with:

```bash
# Modern servers (Intel Haswell+ / AMD Excavator+, enables AVX2, BMI2)
./gradlew :stirling-pdf:nativeCompile -Pnative.arch=x86-64-v3 -PnoSpotless

# Current machine's CPU (not portable — use only for local deployments)
./gradlew :stirling-pdf:nativeCompile -Pnative.arch=native -PnoSpotless
```

## Profile-Guided Optimization (PGO)

PGO teaches the compiler which code paths are actually hot, enabling aggressive
inlining and branch optimization. Typically yields ~15-25% throughput improvement.

### Automated PGO (recommended)
```bash
./scripts/test-native.sh --pgo
```

### Manual PGO Steps

**Step 1: Build with instrumentation**
```bash
./gradlew :stirling-pdf:nativeCompile -Pnative.pgo.instrument -PnoSpotless
```

**Step 2: Run and exercise the application**
```bash
./app/core/build/native/nativeCompile/stirling-pdf -Dserver.port=8080 &
# Perform representative operations: merge, split, OCR, compress, etc.
# Stop the application — this flushes the profile data to default.iprof
kill %1
```

**Step 3: Rebuild with the profile**
```bash
./gradlew :stirling-pdf:nativeCompile -Pnative.pgo.profile=default.iprof -PnoSpotless
```

## Runtime Configuration

### Heap Size
Heap limits are NOT baked into the binary — set them at runtime for flexibility:

```bash
# Recommended for most deployments
./stirling-pdf -Xms128m -Xmx512m -Dserver.port=8080

# Low-memory environments
./stirling-pdf -Xms64m -Xmx256m -Dserver.port=8080

# Heavy workloads (large PDFs, batch processing)
./stirling-pdf -Xms256m -Xmx1g -Dserver.port=8080
```

### Docker
```bash
docker build -f docker/Dockerfile.native -t stirling-pdf-native .
docker run -p 8080:8080 stirling-pdf-native
```

## Garbage Collection

The build uses **Serial GC** (GraalVM Community Edition default):
- Lowest memory footprint
- Single-threaded collection
- Best for services with moderate allocation rates

G1 GC is available in Oracle GraalVM Enterprise but not in Community Edition.
If using Enterprise, change `--gc=serial` to `--gc=G1` in `build.gradle`.

## Configuration Architecture

Native image configuration uses three complementary layers:

1. **Agent-Generated JSON Configs** (`META-INF/native-image/stirling-pdf/`):
   - Auto-generated by GraalVM's `native-image-agent` tracing agent
   - Captures all reflection, JNI, resource, proxy, and serialization metadata
   - Auto-discovered by `native-image` (no flags needed)
   - **This is the primary source of truth** — regenerate when adding new features

2. **Java Runtime Hints** (`NativeImageRuntimeHints.java`):
   - Programmatic, refactor-safe, IDE-friendly
   - Supplements agent-generated config with Spring AOT hints
   - Good for app-specific classes that the agent might miss (e.g., conditional beans)

3. **Reachability Metadata Repository**:
   - Community-maintained metadata for common libraries
   - Pulled automatically by the `org.graalvm.buildtools.native` Gradle plugin
   - Covers Spring Boot, Jackson, Netty, and other ecosystem libraries

### Auto-Generating Config with the Tracing Agent

The recommended workflow uses GraalVM's `native-image-agent` to automatically
generate all native-image config by tracing the running application:

```bash
# Full automated workflow (build → agent run → smoke tests → merge)
./scripts/generate-native-config.sh

# Merge additional code paths into existing config
./scripts/generate-native-config.sh --merge

# Generate + validate for missing registrations
./scripts/generate-native-config.sh --merge --validate
```

**How it works:**
1. Builds the bootJar
2. Starts the app with `-agentlib:native-image-agent`
3. Exercises all API endpoints (smoke tests) to trigger class loading
4. Stops the app — agent flushes config files on JVM exit
5. Merges generated config into `META-INF/native-image/stirling-pdf/`
6. Validates the merged config is well-formed

**Key options:**
- `--merge`: Merge with existing config (add to, don't replace)
- `--validate`: Run with `MissingRegistrationReportingMode=Exit` to detect gaps
- `--port=PORT`: Port to run on (default: 8099)
- `--timeout=SECS`: Startup timeout (default: 120s)
- `--skip-build`: Skip bootJar build if already built

### Gradle Tasks for Config Management

```bash
# Run app under tracing agent (manual — prefer the script above)
./gradlew :stirling-pdf:nativeAgentRun -PnoSpotless

# Copy agent output to META-INF/native-image/
./gradlew :stirling-pdf:nativeAgentCopyConfig -PnoSpotless

# Validate config files are well-formed
./gradlew :stirling-pdf:nativeConfigValidate -PnoSpotless

# Clean agent output
./gradlew :stirling-pdf:nativeAgentClean -PnoSpotless

# Run with MissingRegistrationReportingMode=Exit to find gaps
./gradlew :stirling-pdf:nativeAgentValidateRegistrations -PnoSpotless
```

### Agent Filters

Two filter files control what the agent records, keeping config lean:

- **`agent-caller-filter.json`**: Only record accesses triggered by relevant
  packages (stirling, pdfbox, bouncycastle, verapdf, etc.)
- **`agent-access-filter.json`**: Exclude internal JDK classes that don't need
  explicit registration (jdk.internal, jdk.jfr, etc.)

Both live in `META-INF/native-image/stirling-pdf/` and are automatically used
by `generate-native-config.sh`.

### Docker Build with Agent

The Docker build can optionally run the tracing agent during the build stage:

```bash
# Standard Docker build (uses committed config)
docker build -f docker/Dockerfile.native -t stirling-pdf-native .

# Docker build with tracing agent (auto-generates fresh config)
docker build -f docker/Dockerfile.native --build-arg RUN_AGENT=true -t stirling-pdf-native .
```

### Iterative Config Improvement Workflow

When adding new features or encountering "missing reflection" errors:

1. **Reproduce**: Run the native binary and trigger the failing operation
2. **Generate**: Run `./scripts/generate-native-config.sh --merge`
   - The `--merge` flag adds new entries without losing existing ones
3. **Validate**: Run `./scripts/generate-native-config.sh --merge --validate`
   - Detects remaining gaps via `MissingRegistrationReportingMode=Exit`
4. **Build**: `./gradlew :stirling-pdf:nativeCompile -PnoSpotless`
5. **Test**: Run the native binary and verify the fix
6. **Commit**: Commit the updated config files

### Keeping the Binary Lean

The agent-generated config can be over-broad. To keep the binary small:

1. **Use agent filters**: The `agent-caller-filter.json` and
   `agent-access-filter.json` ensure only relevant classes are recorded
2. **Conditional metadata**: GraalVM supports `"condition": { "typeReachable": "..." }`
   — entries are only applied if the related code is reachable in the final image
3. **Don't over-approximate**: The agent records only what is actually hit during
   the traced run, which is inherently more precise than manual "register everything"
4. **Spring AOT**: Spring Boot 4's AOT engine pre-computes most Spring-internal
   reflection needs, so the agent mainly captures third-party library usage

## Build-Time vs Runtime Initialization

| Initialized At | Classes | Why |
|----------------|---------|-----|
| **Build time** | `Standard14Fonts`, `Standard14Fonts$FontName` | Pure enum/static data, safe |
| **Runtime** | `sun.awt.*`, `sun.java2d.*`, `sun.font.*`, `java.awt.*` | Native JNI state |
| **Runtime** | `org.hibernate.*`, `javax.persistence.*`, `org.h2.*` | Database connections |

**Rule of thumb**: If a class's static initializer touches files, sockets, RNG, or
native libraries, it MUST be initialized at runtime.

## Known Limitations

- **First-run Latency**: Some PDF operations may be slower on the very first
  execution (no JIT warmup in native image).
- **Dynamic Class Loading**: All classes must be known at build time. Plugins or
  dynamic extensions are not supported in native mode.
- **AWT**: Requires system libraries (`libawt.so`, `libfontmanager.so`, etc.)
  which are bundled in the Docker container at `/app/jdk-libs/`.
- **G1 GC**: Only available in Oracle GraalVM, not Community Edition.

## Troubleshooting

### "Class Verification Failed"
Check `reflect-config.json` and ensure the class is registered, or add it to
`NativeImageRuntimeHints.java`.

### "Resource not found"
Add the resource pattern to `resource-config.json` or register it in
`NativeImageRuntimeHints.registerResourceHints()`.

### "No instances of ... are allowed in the image heap"
A class was initialized at build time but holds a file handle, socket, or native
state. Add it to `--initialize-at-run-time` in `build.gradle`.

### Build warnings about experimental options
All experimental flags (`-H:+UnlockExperimentalVMOptions`,
`-H:ReflectionConfigurationFiles=...`) have been removed. JSON configs are
auto-discovered from `META-INF/native-image/` on the classpath.
